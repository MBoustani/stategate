How it works Docs GitHub

Your agent's prompt asks. stategate enforces.

AI agents choose their own tool calls. stategate checks every call against rules and a trusted state the agent can't change. If the rules aren't met, the tool doesn't run, and the agent is told what to do first.

Trusted state (the agent can read it, never write it)

A prompt is a request, not a rule

Long conversations, persuasive users and prompt injections can all make a model skip a step it was told never to skip. When a tool moves money, deletes data or sends email, that isn't good enough.

Rules in the prompt

The model is asked to behave. Nothing checks that it did.

"Always verify the customer before issuing a refund."

Rules in stategate

Code checks every call before it runs. The model can't argue its way past it.

requires: state.identity_verified == true

How it works

You describe the rules once, in a short YAML file. The dependency graph between tools is worked out for you.

  1. Declare the trusted state

    A few typed variables your agent depends on. The agent can read them. Only successful tool calls, or your own application code, can change them.

    state:
  identity_verified: { type: bool, default: false }
  order_id:          { type: str }
  order_total:       { type: float }
  order_status:      { type: str, default: none }

  2. Give each tool its rules

    What must be true before it runs, which arguments are allowed, how often it can run, and how the state changes when it succeeds.

    issue_refund:
  requires:
    - state.identity_verified == true
    - state.order_status == "found"
    - args.order_id == $state.order_id   # only the order we looked up
    - args.amount <= $state.order_total  # never more than was paid
  max_calls: 1
  effects:
    - { set: order_status, value: refunded }

  3. Every call is checked

    If a rule fails, your function is not called. The agent gets the reason and a suggested order of calls, so it can recover on its own.

    BLOCKED: `issue_refund` was not executed.
Unmet requirements:
  1. state.identity_verified == true  (currently false)
     -> can be satisfied by calling: verify_identity
  2. state.order_status == "found"  (currently "none")
     -> can be satisfied by calling: lookup_order
Suggested order: verify_identity -> lookup_order -> issue_refund

Fits the SDK you already use

Wrap your tools with one function. Names, signatures and docstrings stay the same, so the model sees the same tools as before.

Other frameworks can use the small core API directly.

from stategate import Guard, Policy
from stategate.adapters.openai_agents import guarded_function_tool

guard = Guard(Policy.from_file("policy.yaml"))  # one per conversation

agent = Agent(
    name="Support agent",
    tools=[
        guarded_function_tool(guard, verify_identity),
        guarded_function_tool(guard, lookup_order),
        guarded_function_tool(guard, issue_refund),
    ],
)
from stategate import Guard, Policy
from stategate.adapters.claude_agent_sdk import guarded_tool, guard_hooks

guard = Guard(Policy.from_file("policy.yaml"))  # one per conversation

@guarded_tool(guard, "issue_refund", "Refund an order",
              {"order_id": str, "amount": float})
async def issue_refund(args):
    return payments.refund(args["order_id"], args["amount"])

# optional: also guard built-in tools like Bash
options = ClaudeAgentOptions(hooks=guard_hooks(guard), ...)

Review the rules like code

A policy protects you, so check it before your agent runs. The checker finds typos, type mistakes and tools that can never run because of a circular dependency.

# find mistakes in the policy
stategate check policy.yaml

# draw the tool dependency graph
stategate graph policy.yaml --markdown -o GRAPH.md

# what does a tool need, and in what order?
stategate explain policy.yaml issue_refund
